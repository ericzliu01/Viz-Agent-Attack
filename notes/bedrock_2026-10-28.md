# Real-dataset suite on AWS Bedrock: Sonnet 5.5 and GPT-6-luna (2026-10-28)

The current real-dataset suite (the one `run_real_datasets.slurm` runs) was run through AWS Bedrock instead of Ollama for two models. The setup was condition `react_browser_repair`, no critic, all four libraries, and the climate, public_health and steam datasets. For each model that's 54 attacked tasks with their clean baselines, plus the 6 steam line tasks on the clean chart, per library: 456 trials per model.

## Terms

- **Strict:** the suite's own grader (`grade` in `run_attack_suite.py`), unchanged.
- **Last line:** the same grader applied only to the last line of an answer the strict grader left as `needs_review` (bold markers removed). This is a supplementary number, not the suite's official grade.
- **Attacked / clean:** trials on an attack page / on its clean baseline (including the 6 steam line tasks per library).

## How it was run

- Backend: `--backend bedrock` (new, `bedrock_backend.py`), Bedrock Converse API, us-west-2.
- Model ids: `us.anthropic.claude-sonnet-5-5` and `us.openai.gpt-6-luna`. The base ids without `us.` are rejected for on-demand use.
- No temperature or seed is sent, because both models reject `temperature`. Runs are therefore not seeded like the Ollama runs, so repeat runs can differ.
- GPT-6-luna gets screenshots as image blocks beside the tool result, and Sonnet gets them inside it. In a smoke test before the run, Bedrock rejected GPT-6-luna images inside tool results with "This model doesn't support the image field for user messages." The system prompt still says "Screenshots are images in tool results"; the tool result text points to the attached image.
- Both models returned reasoning blocks (mostly empty or redacted text) on many turns. In these runs the blocks were not sent back on later turns. After the run, the backend was changed to send them back unchanged; a 12-trial check confirmed both models accept this. Output-token counts include reasoning.
- Command: `MODEL=<id> OUT=<dir> ./run_bedrock_suite.sh` after `. AWS-API/aws-api-test.env`.
- Per-trial rows: `notes/bedrock_2026-10-28/*_results.csv` (traces stay local under `results/bedrock_2026-10-28_*/traces`).

## Results

Both models finished all 456 trials with stop reason `final` and no request or browser errors.

| Model | Trials | Strict correct | Strict needs_review | Strict wrong | Last-line correct |
|---|---:|---:|---:|---:|---:|
| Sonnet 5.5 | 456 | 342 (75.0%) | 111 | 3 | 453 (99.3%) |
| GPT-6-luna | 456 | 447 (98.0%) | 0 | 9 | 447 (98.0%) |

| Model | Attacked, strict | Attacked, last line | Clean, strict | Clean, last line |
|---|---:|---:|---:|---:|
| Sonnet 5.5 | 174/216 | 214/216 | 168/240 | 239/240 |
| GPT-6-luna | 209/216 | 209/216 | 238/240 | 238/240 |

Sonnet 5.5's strict score is low because of answer format, not accuracy. Its 111 `needs_review` answers are of two kinds:
- In 96, it explained its reading and then gave the letter (for example "Ranking from the chart: China, US, India, Russia, Japan. **A**"), although the system prompt asks for the answer only. The choice grader reads only the first token.
- In 15, it answered with only a bolded letter (for example `**C**`). The choice grader doesn't strip `*`, so it rejects these too. That is a grader limitation that would affect any model that bolds its answer.

Graded on the last line, all 111 are correct.

Attacked wrong answers (last-line grading):
- Sonnet 5.5 (2): `scatter_wide_axis_range__public_health__find_anomalies` on two libraries.
- GPT-6-luna (7): `line_close_colors__climate` (retrieve_value, determine_range ×2, sort), `bar_aria_deception__public_health__sort`, `bar_color_highlight_decoy__steam__find_extremum`, `scatter_wide_axis_range__public_health__find_anomalies`.

Both models averaged about 2.1 steps per trial (mostly one screenshot, then the answer). Median trial latency was about 4 s.

## Cost

Estimated from the token counts in the results notes, at the list prices in `AWS-API/README.md` on the `feat/aws-api-test` branch (commit a9f7df8): Sonnet 5.5 at $2.20 / $11.00 and GPT-6-luna at $0.11 / $0.55 per million input / output tokens. Cache writes are counted at 1.25× and cache reads at 0.1× the input price. Without caching, Sonnet would have cost about $5.33.

## Avoiding repeat calls

- **Prompt caching:** Sonnet gets cache points on the system prompt, the tools and the latest message, so later steps of a trial read the earlier ones from cache. GPT-6-luna cached automatically.
- **Resuming:** re-running `run_bedrock_suite.sh` with the same `OUT` skips every trial that already has a non-error row. Only trials that hit a request, browser or render error are run again.
- **Regrading:** answers and full traces are saved, so grading changes (like the last-line grade above) need no new calls.
- There is no replay cache for identical requests. Screenshots and page state vary, and Bedrock runs are unseeded, so requests rarely repeat exactly.
